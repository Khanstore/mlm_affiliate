Overview

Introduction & Architecture

The MLM Affiliate module transforms your Odoo 18 store into a full multi-level marketing referral network. Every registered affiliate gets a unique referral link; when a buyer follows that link and places an order, commissions are automatically distributed across multiple upline levels — all without manual intervention.

ℹ️
L1 Split Rule

If the buyer already has their own upline (they were previously referred), the Level 1 commission is split 50/50 between the external referrer and the buyer's upline. This prevents double-crediting conflicts.

Before Installing

If upgrading from a prior version, run these SQL commands directly in your database first to prevent a column-missing error, then restart Odoo before upgrading from the UI:

Commission Rules

Commission rules define how much total commission a product sale generates. This total "pot" is then distributed across MLM levels according to the Level Rates (Chapter 4).

Rule Types & Priority

When an order line is processed, the engine searches for the most specific matching rule:

PriorityRule TypePricelistUse When
1Specific VariantPricelist-specificUnique rate for one variant × pricelist
2Product (Template)Pricelist-specificAll variants of a product × pricelist
3CategoryPricelist-specificEntire category × pricelist (walks up tree)
4Specific VariantPublic / AnyUnique rate for one variant, all buyers
5Product (Template)Public / AnyAll variants of a product, all buyers
6CategoryPublic / AnyCatch-all by category (walks up tree)
💡
Category Tree Walk

For category rules, if no rule matches the product's direct category, Odoo walks up the parent categories until it finds a match. This lets you set one rule on "All" and override specific sub-categories.

Affiliate Tiers

Tiers give affiliates a visible progression path and allow you to reward your top performers with commission multipliers. Tier assignment is automatic — recalculated every time an affiliate's commission is approved.

Tier Pyramid

🥇 Gold ≥ ৳50,000 earned · ≥ 20 referrals ×1.25
🥈 Silver ≥ ৳15,000 earned · ≥ 10 referrals ×1.10
🥉 Bronze ≥ ৳2,000 earned · ≥ 2 referrals ×1.05
⭐ Starter New affiliate · no minimum ×1.00

Creating a Tier

1
Go to MLM Affiliate → Configuration → Affiliate Tiers
Click New to open the tier form.
2
Set Tier Name & Thresholds
Enter Min. Total Earned (cumulative lifetime earnings in your currency) and Min. Direct Referrals (number of downline partners).
3
Set Commission Multiplier
Default is 1.0 (no bonus). Set 1.25 for a 25% bonus on all commissions earned by affiliates at this tier.
FieldDescription
Tier NameTranslatable label shown to the affiliate on their portal page
Min. Total EarnedLifetime cumulative approved/paid commissions required
Min. Direct ReferralsNumber of partners with this affiliate as their upline
Commission MultiplierAll commissions for affiliates in this tier are multiplied by this factor
🤖
Automatic Tier Promotion

Every time a payment is validated and commissions are auto-approved, the system calls action_update_tier() on every affected earner. The affiliate is assigned the highest tier they qualify for — no manual action needed.

Auto-Approval on Payment

🤖
Fully Automatic — No Manual Step Required

When an invoice transitions to in_payment or paid, all pending commissions on the linked sale orders are automatically approved. Email notifications are sent to each earner, and their affiliate tier is recalculated. A chatter note is posted on the sale order for full traceability.

To manually approve or manage commissions (e.g., for corrections), open a commission record and use the action buttons at the top of the form.

Wallet & Payout Methods

Every affiliate has a virtual Wallet Balance — a running total of approved commissions not yet paid out or spent at checkout.

Wallet Balance Formula

💼 Wallet Balance Calculation
Approved wallet commissions + ৳3,200.00
Paid-out wallet commissions − ৳800.00
Wallet spent at checkout − ৳550.00
Current Wallet Balance ৳1,850.00

Three Payout Methods

MethodHow it worksWhen to use
🏦 Wallet Credit Commission added to affiliate's internal wallet. Can be spent at checkout or cashed out later. Default. Great for encouraging repeat purchases.
💸 Bank Transfer Admin manually transfers to the bank account stored in affiliate_bank_account, then marks commission as Paid. Cash-heavy affiliate programs.
🎟️ Discount Coupon When marked as Paid, a unique coupon code (format: AFF-XXXXXXXX) is auto-generated and stored on the commission record. Product-based referral incentives.

Using Wallet at Checkout

1
Affiliate logs in to your eCommerce store
The wallet balance is shown in the cart and checkout pages.
2
Apply wallet balance
The affiliate clicks "Use Wallet Credit" at checkout. The wallet_amount_used field on the sale order records the deducted amount.
3
Balance updated automatically
Once the order is confirmed and paid, the wallet balance recalculates, deducting the used amount.
ℹ️
Minimum Payout Threshold

Set a minimum payout threshold in Settings. Commissions below this value cannot be marked as Paid via bank transfer or coupon — the system raises a user-friendly error. Wallet credits are not affected by the threshold.

Affiliate Portal Dashboard

Logged-in affiliates can visit /my/affiliate to see:

  • Their unique referral link with one-click copy and social share buttons
  • Wallet balance and commission history
  • Link click count and last click date
  • Current tier and progress toward the next tier
  • Direct downline list

Click Tracking

Every visit to a referral URL increments referral_click_count and updates referral_last_click on the affiliate's partner record. Admins can see these fields in the contact form under the MLM tab.

💡
Open Graph / Social Sharing

The module includes og_redirect_template.xml which sets proper Open Graph meta tags on the referral redirect page, so when affiliates share their link on social media, it shows a branded preview card instead of a blank redirect.

Troubleshooting

Common Issues

❌ "column res_partner.tier_id does not exist" on upgrade

🔧
Fix

Run the following SQL directly in PostgreSQL, then restart Odoo before upgrading:

ALTER TABLE res_partner ADD COLUMN IF NOT EXISTS tier_id INTEGER;
ALTER TABLE res_partner ADD COLUMN IF NOT EXISTS affiliate_bank_account TEXT;
ALTER TABLE res_partner ADD COLUMN IF NOT EXISTS referral_click_count INTEGER DEFAULT 0;
ALTER TABLE res_partner ADD COLUMN IF NOT EXISTS referral_last_click TIMESTAMP WITH TIME ZONE;

❌ Commissions not created after order confirmation

  • Check the sale order has a Referred By (referrer_partner_id) set. If the referral cookie wasn't set, no referrer is attached and no commission is generated.
  • Ensure a Commission Rule matches the product. Check Configuration → Commission Rules and verify the rule type and target match your product.
  • Ensure at least one Level Rate is active.

❌ Commissions not auto-approving on payment

  • Verify the invoice is linked to the sale order (sale order → Invoices button shows the invoice).
  • The trigger fires when payment_state changes to in_payment or paid. COD orders require manually registering payment on the invoice — the transaction record alone is not enough.
  • Check the Odoo server log for any Python errors during the payment write.

❌ "Active level rates must sum to exactly 100%" error

  • Go to Configuration → Level Distribution Rates and verify your active rates add up to exactly 100%.
  • If you have 3 levels at 86%, 10%, 4% — that sums to 100% ✓.

❌ "Invalid field 'numbercall' on model 'ir.cron'"

🔧
Fix

Remove the line <field name="numbercall">-1</field> from data/cron_data.xml. This field was removed in Odoo 18.

❌ Referral link not tracking the referrer

  • Ensure the visitor visits the /ref/{CODE} URL before adding to cart.
  • The referrer code is stored in a browser cookie (mlm_ref). If cookies are disabled or cleared, tracking won't work.
  • The referrer won't be attached if the buyer is the same partner as the referrer (self-referral prevention).
💡
Need More Help?

Enable debug mode in Odoo (Settings → Activate Developer Mode) to see detailed field names and model technical info. Check the server log at the path shown in your Odoo configuration file for full Python tracebacks.
